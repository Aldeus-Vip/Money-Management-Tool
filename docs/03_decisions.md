# 決定事項 (v0.2)

`02_open-questions.md` への回答を反映したもの。

## 1. 構成

| 項目 | 決定 |
|---|---|
| 利用端末 | PC + スマホ |
| DB | SQLite ファイルを OneDrive に配置。**同時編集なし** (排他制御は簡易でよい) |
| ホスティング | GitHub Pages (アプリのコードのみ) |
| データの扱い | **個人データ (Excel・DBファイル・実際の金額や用途名) は GitHub に push しない**。リポジトリには架空のサンプルデータのみ置く |
| 認証 | アプリ起動時に PIN |
| 技術 | React + TypeScript + Vite / SQLite (WASM) |

### DB接続の段階

| 段階 | PC | スマホ |

| Phase 1 | OneDrive同期フォルダ内の .sqlite をブラウザで直接開く (Chrome/Edge) | — |

## 2. 連携先

| 連携先 | 方針 |

| OneDrive | Graph API (Phase 3) |
| 祝日 | 給料日の前倒し判定に使用 (内蔵データ or 無料 API) |

## 3. データ管理の考え方 (Q6)

- **月ごとのファイル分割を廃止**。全取引を1つのDBで管理する
- 表示は従来どおり **給料日起点の期間単位** (期間セレクタで切替)
- 過去の期間も閲覧可能
- 給料の登録 = 新しい期間の開始 (収入データの更新)
- **繰越ルールは保留**。開発を進めた後、「どの金額をどこに加えるか」を個別に相談して決める

## 4. 機能の取捨 (Q7)

以下は **すべて不要** (実装しない)。

- 食事記録・料理原価
- 自販機の組合せ逆算
- 次回予定のリマインド
- 消費税フラグ
- 弁当代の簡易計算
- C'K (確認済) フラグ → 全行を集計対象とする

## 5. 計算ルール (Q8)

- 水道代の推定額 ×2: **2ヶ月に1回の請求**のため、月平均が半分になるのを補正する目的。
  → アプリでは固定費マスタに「請求周期 (月数)」を持たせ、`推定額 = 月平均 × 周期` として一般化する。
