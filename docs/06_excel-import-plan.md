# Excel 取り込みの準備 (2023年10月〜)

形式が時期によって異なるため、**実際の取り込み処理はファイルを確認してから実装する**。
ここでは、受け皿として用意したものと、最新形式 (2026年10月版) の対応案をまとめる。

## 1. 用意済みの受け皿

| 仕組み | 内容 |
|---|---|
| 取り込み単位 (`import_batches`) | 1ファイル = 1単位。取り込んだ行には `batch_id` が付く |
| やり直し | 設定画面から単位ごとに削除 → 再取り込み。手入力のデータは消えない |
| 月次実績 (`monthly_actuals`) | 明細が無く集計値だけの月の受け皿。分析画面の費用実績に「*」付きで表示 |
| 期間の開始日 | Excel の給料日 (使用状況!E2 等) をそのまま `periods.start_date` に保存できる |

## 2. 最新形式 (2026_10) の対応案

| Excel | 取り込み先 |
|---|---|
| 年月設定 B2:C2 | 期間の ym |
| 目的設定 D4 (給料), E4/G4 (賞与/ON), D26 (食費予算) | `periods` |
| 目的設定 K11/K12 (課金・娯楽上限), K17/K18 (貯金・娯楽移動) | `periods` |
| 目的設定 C7:D22 (固定費) / 銀行口座 E9:G25 (支払予定・D列=済) | `fixed_costs` (名前で照合) + `period_fixed_costs` |
| 銀行口座 G3 / 現金・PayPay・Suica の E3 (給料前残高) | `period_balances.opening` |
| 現金・PayPay F7 (現在の所持金) | `period_balances.actual` |
| 銀行口座 E28:G64 (出金/手数料/PayPay/Suica/入金) | `transfers` (+手数料は取引) |
| 銀行口座 E28:G64 (振込) | 普通口座の受取金 |
| デビット決済 B:F | デビットの取引 (区分・用途) |
| 現金 / PayPay / Suica B:H (C'K=1 の行) | 取引 (C'K=0 の行の扱いは要相談) |
| 銀行口座 O14:S27 (娯楽費・貯金使用表) | `pool_entries` (use) |
| 銀行口座 Q2/Q3 (仮移動後の残高) | 最初の月のみ `pool_entries` (adjust) |
| 費用実績 E4:P43 | 明細の無い月の `monthly_actuals` |

## 3. 取り込み時に相談したいこと

- 形式の違い (シート名・列の位置・項目の有無) の一覧化 — 各時期のファイルを 1 つずつ確認
- C'K=0 (未確認) の行を取り込むか
- 用途名の揺れ (例: 同じ店の表記違い) を統合するか
- 繰越ルール (期首残高と自由枠) — Phase 2 の結果を見て決定
- 費用実績の値と明細の合計が食い違う月の扱い
