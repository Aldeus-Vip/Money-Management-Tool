### 1-2. 機能カテゴリ

**A. 期間・予算設定**
- A1 対象期間の選択 (年月 → 給料日ベースの期間を自動算出)
- A2 収入入力: 今月の給料 / 賞与(ON/OFFフラグ)
- A3 固定費の予算: マスタから選択 → 予定額を自動取得
- A4 食費予算 (手入力) + **推奨値** = 過去の食費平均 × 1.05
- A5 自由枠 = 給料 + 賞与 − 固定費合計 − 食費予算
- A6 自由枠の配分: 課金上限 / 娯楽費その他上限 / 貯金移動 / 娯楽費移動 → 残りが **臨時費用枠**
- A7 臨時費用の **推奨最低額** = 過去(交通費+臨時費用+手数料)平均 × 1.05 + 最低額(5,000)

**B. 固定費管理**
- B1 固定費マスタ: 名称 / 引落日 / 予定額 / バッファ(+10%)フラグ
- B2 予定額の自動推定 = 費用実績の過去平均 × (1 + 10%)。水道代は隔月請求のため ×2
- B3 引落予定表: 引落日順に並べ、「引落済」チェック
- B4 支払済/未払の切替で口座残高の見込みを再計算 (全額控除モード / チェック済のみ控除モード)

**C. 口座・ウォレット管理** (普通口座 / 現金 / PayPay / Suica / デビット)
- C1 各ウォレットの「給料日前残高」(期首残高)
- C2 口座入出金: 出金 / 手数料 / デビット決済 / PayPayチャージ / Suicaチャージ / 入金 / 振込
- C3 チャージ・出金は **ウォレット間の移動** として扱う (銀行→現金、銀行→PayPay 等)
- C4 計算上残高 vs 実残高の入力 → **差額 = 不明金** (+なら使途不明、−なら記録漏れ収入)
- C5 消費税フラグ (現金のみ。8% を加算)
- C6 「受取金」区分 = 収入として残高・自由枠に加算
- C7 C'K (確認済) フラグ: 1 の行だけ集計に含める

**D. 支出記録**
- D1 区分: 食費 / 交通費 / 娯楽費 / 臨時費用 / その他 / 受取金
- D2 用途: ウォレット別のプルダウン候補 (例: 会社弁当、コンビニ、朽網-小倉 …)
- D3 デビット決済: 銀行側で金額・日付を入れると一覧に自動反映 → 区分/用途だけ後付け
- D4 用途別集計 (回数・合計) と、合計>0 のものだけのランキング
- D5 弁当代の簡易計算 (400円 × 日数)

**E. 貯蓄・娯楽費プール**
- E1 貯金 / 娯楽費の残高 (仮移動後の値)
- E2 今月の移動額 (目的設定から)
- E3 プールからの使用記録 (用途/金額/日付/種別) → 臨時費用補填・課金 等

**F. 分析・可視化**
- F1 日別×区分の支出表 (期間内の全日)
- F2 予算消化ペースグラフ: 実績累計 vs 理想ライン (食費・臨時費用)
- F3 食費: 実食費 vs 計算食費の差異チェック
- F4 費用実績: 月別の固定費・変動費・入出金と年平均・前年平均
- F5 枠のサマリ表示: 「食費 ¥x / ¥y 残り ¥z」「臨時費用 …」「課金 …」

**G. 警告 (条件付き書式の置換)**
- 自由枠 < 0、臨時費用残 < 推奨額、口座残高 < 0、不明金あり、実食費≠計算食費 → 赤表示

**H. その他**
- H1 次回予定のリマインド (例: 通院日時。当日ハイライト)
- H2 食事記録・料理原価計算 (非表示シート群)
- H3 自販機の組合せ逆算 (非表示)

### 1-3. Web化で自動化できる「手作業」

| 現状 (Excel) | Web化後 |
|---|---|
| 毎月ファイルを複製、給料日前残高を手入力 | 前期間の **期末残高を自動繰越** |

## 2. API整理 (連携可能 / 不能)

判定基準: **個人が自分のWebアプリから正規に使えるか**。

| 連携先 | 判定 | 理由 / 代替 |
|---|---|---|
| 銀行口座 (普通口座) | ❌ 原則不可 | 銀行APIは「電子決済等代行業者」登録が前提で個人は直接使えない。→ **CSV取込**で代替 (銀行により可否が違う) |
| デビットカード | ❌ 不可 | 同上。銀行CSVに含まれることが多い |
| PayPay | ⚠️ API不可 / **CSV可** | PayPay for Developers は加盟店向け。アプリから取引履歴CSV (過去2年、1回1年まで) がダウンロード可能 → **CSV取込** |
| Suica (モバイルSuica) | ❌ 不可 | 公式APIなし、公式CSVもなし。Web NFCはFeliCa非対応。→ 手入力 (または会員サイトの履歴を手でコピー) |
| 電気・ガス・水道 | ❌ 不可 | 公開APIなし。→ 固定費として手入力 |
| サブスク (Amazon Prime, Microsoft, Claude, Netflix, YouTube, PlayStation, Adobe, 任天堂, FOD, NHK 等) | ❌ 不可 | 利用者向け請求APIなし。→ 固定費マスタで管理 |
| Zaim (家計簿アグリゲータ) | ⚠️ 要検証 | 個人開発者向けAPIあり。ただし銀行明細が取れるかは未確認 → 将来候補 |
| OneDrive (Microsoft Graph) | ✅ 可 | 個人Microsoftアカウントで OAuth 可。**DBファイルの保存先**として使用 |
| Google Drive | ✅ 可 | 同上 (候補) |
| 日本の祝日 | ✅ 可 | 無料API / 内閣府CSV。給料日の前倒し判定に使用 |
| 為替レート | ✅ 可 | 無料API あり (「為替誤差」用途。任意) |

**結論**: 金融系はほぼ API不可。現実解は **「CSV取込 + 手入力」**。API が使えるのは「保存先 (OneDrive)」と「補助データ (祝日)」。

## 3. システム構成案 (DB方式)

要件: 「DBはLocal / アプリはWeb / OneDrive上でも動く」

### 案A (推奨): ブラウザ完結型 PWA + SQLite ファイル

```
[Webアプリ (静的ホスティング: GitHub Pages 等)]
        │  ブラウザ内で SQLite (WASM) を実行
        ├─ PC: File System Access API で ローカル/OneDrive同期フォルダの .sqlite を直接開く
        └─ スマホ: Microsoft Graph API で OneDrive 上の .sqlite を読み書き
```

- 長所: サーバ不要 / データは自分のPC・OneDriveにしか置かれない / 1ファイルでバックアップ容易
- 短所: File System Access API は **PCのChrome/Edgeのみ**。スマホは Graph API 経由が必要
- 注意: 同時に2台で書き込むと競合 → **ロック or 最終更新時刻チェック**で対策

### 案B: ローカルサーバ型

```
[PCで常駐する小さなサーバ (Node等) + SQLite] ← ブラウザで localhost を開く
```

- 長所: 実装が素直、どのブラウザでも可
- 短所: PCを起動していないとスマホから使えない、インストールが必要

### データモデル (概略)

| テーブル | 主な項目 |
|---|---|
| periods | 年月, 開始日, 終了日, 給料, 賞与, 賞与ON, 食費予算, 課金上限, 娯楽費上限, 貯金移動, 娯楽費移動 |
| wallets | 普通口座 / 現金 / PayPay / Suica / (デビットは口座に紐付け) |
| wallet_balances | 期間 × ウォレット: 期首残高, 実残高 (不明金チェック用) |
| transactions | 日付, ウォレット, 区分, 用途, 金額, 税フラグ, 確認済 |
| transfers | 日付, 移動元, 移動先, 種別 (出金/チャージ/入金/振込/手数料), 金額 |
| fixed_costs | 名称, 引落日, 推定方式, バッファ有無, 有効/無効 |
| fixed_cost_payments | 期間 × 固定費: 予定額, 実額, 引落済 |
| pools / pool_moves | 貯金・娯楽費のプール残高と使用記録 |
| purposes | 用途マスタ (ウォレット別候補, 既定の区分) |
| reminders | 次回予定 (タイトル, 日時) |
| meals / meal_items (任意) | 食事記録・料金リスト |
